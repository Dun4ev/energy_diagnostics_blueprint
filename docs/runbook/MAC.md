# Продолжение работы на MacBook

В репозитории находятся исходный код приложения, подготовленный пакет стенда, сценарии показа и материалы роликов. Репозиторий публичный. Пароли, локальная PostgreSQL-база, резервные копии и временные кадры видео в Git не входят.

## Получить проект

Если проекта на Mac еще нет, в терминале перейдите в папку, где хотите его хранить, и выполните:

```bash
git clone https://github.com/Dun4ev/energy_diagnostics_blueprint.git
cd energy_diagnostics_blueprint
```

Если проект уже есть, сначала проверьте его состояние. При собственных незакоммиченных изменениях не очищайте их: сначала разберите их отдельно.

```bash
cd /путь/к/energy_diagnostics_blueprint
git status --short --branch
git remote -v
git pull --ff-only origin main
```

`git pull --ff-only` не переписывает локальную историю и остановится, если требуется ручное объединение. Не используйте `reset --hard` или `clean` для обхода ошибки.

## Запустить приложение

Нужны Python 3, Docker Desktop и доступ к интернету при первой сборке образов и загрузке зависимостей. Запустите Docker Desktop. В корне основного checkout выполните:

```bash
python3 scripts/init_local_env.py
docker compose --env-file infra/.env -p energy-diagnostics -f infra/compose.yaml config --quiet
docker compose --env-file infra/.env -p energy-diagnostics -f infra/compose.yaml up --build -d --wait
docker compose --env-file infra/.env -p energy-diagnostics -f infra/compose.yaml ps
curl --fail --silent --show-error http://127.0.0.1:8080/api/v1/health
```

Откройте `http://127.0.0.1:8080/stand` для автоматической записи или `http://127.0.0.1:8080/` для входа в приложение. Роли: `engineer`, `viewer`, `approver`, `technician`, `admin`. Для перехода от записи стенда к живому показу подходит `engineer`.

На новом компьютере скрипт создает собственные пароли в `infra/.env`, не печатая их. Чтобы скопировать пароль инженера в буфер обмена macOS, не выводя его в терминал:

```bash
sed -n 's/^DEMO_ENGINEER_PASSWORD=//p' infra/.env | pbcopy
```

Для другой роли замените `ENGINEER` на `VIEWER`, `APPROVER` или `TECHNICIAN`. Не показывайте файл с паролями аудитории. Если проект уже работал на Mac, сохраните существующий `infra/.env` и Docker volume: новая генерация паролей при старой базе может привести к несовпадению учетных данных.

Автопоказ после подготовки web-образа можно запустить без API и интернета командой:

```bash
docker compose --env-file infra/.env -p energy-diagnostics -f infra/compose.yaml up --no-build --pull never --no-deps -d web
```

Для живого разбора нужен полный стек. Виртуальное время и режим SIMULATION обозначены в интерфейсе; приложение не управляет оборудованием. Подробности: [стенд](STAND.md), [сценарий показа](PRESENTATION.md), [локальный runbook](LOCAL.md).

## Что переносится и что нет

Git переносит код, фикстуры и готовый пакет записи. Ранее созданные на Windows учебные запуски, решения и пароли находятся в локальной базе и `infra/.env`, поэтому новый запуск на Mac не содержит их автоматически. Перед передачей проекта на Windows создана резервная копия в игнорируемой папке `infra/.env.backups/`; она содержит данные базы и не опубликована в GitHub. Если нужна именно прежняя история, ее переносите отдельно через защищенный канал и отдельно согласуйте восстановление: не перезаписывайте существующую базу Mac. Проверка списка содержимого архива не равна проверенному восстановлению рабочей базы.
