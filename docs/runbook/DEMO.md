# Демонстрация на 7–10 минут

Это локальный советчик на синтетических данных. Он не подключен к оборудованию и не отправляет команды. Инженерная приемка на реальном объекте не выполнялась.

1. Открыть http://127.0.0.1:8080. Войти как engineer с локальным паролем из infra/.env (DEMO_ENGINEER_PASSWORD). Начать с REFERENCE: числа слайда 7,2/10, 80/68/+12 °C являются иллюстрацией. Индекс не означает 72% вероятности. Состояние Т-2 на схеме неизвестно.
2. Выбрать SIMULATION, последний срез. Дождаться завершения расчета. Время данных относится к июлю 2026, а не к текущему времени компьютера. Девять активов рассчитываются из observations; эталонные данные truth сервисам недоступны.
3. В очереди открыть ТП-177 или ТП-309: сравнить измеренную и ожидаемую температуру, затем остаток, тренды и качество. Объяснить разницу между сигналом, неподтвержденной гипотезой и решением инженера.
4. Сравнить ТП-305 (нагрузка растет, но остаток не показывает контактного нагрева), ТП-306 (расхождение датчиков), ТП-307 (недостаточно свежих данных). Неизвестная оценка не равна низкому риску. Для выключателя/кабеля тепловой метод не применяется.
5. В случае записать основание рассмотрения и синтетическое доказательство. Термограмма не выдумывается: отсутствие изображения указывается явно. Создать проект проверочного плана, определить действия, сроки, исполнителей и требуемые подтверждения. Сохранить и передать на согласование.
6. В отдельном браузере открыть ту же ссылку плана и войти как approver (DEMO_APPROVER_PASSWORD). Утвердить или вернуть с причиной. Пользователь viewer не может утвердить план даже прямым HTTP-запросом. Если изменился анализ/доказательства, потребуется повторное рассмотрение.
7. Для результата проверки войти как technician (DEMO_TECHNICIAN_PASSWORD). Результат и доказательства сохраняются отдельно от их проверки. Само снижение температуры не закрывает случай. Для закрытия нужны выполненные условия workflow и явное решение уполномоченного пользователя.
8. Показать историю и экспорт: режим, время, версия модели/политики и происхождение данных сохраняются. Для воспроизведения нормального периода начать новый SIMULATION run с ранним временем; пауза/шаг/скорость относятся к виртуальному времени. Перемотка назад создает другой run, история текущего не стирается.

Перед показом проверить актуальный результат verification/PROTOTYPE_ACCEPTANCE.md. Если такого принятого отчета еще нет, интеграционная и визуальная приемка остается незавершенной. Список локальных проверок не является промышленной сертификацией или оценкой эксплуатационной точности модели.
