# Репетиция показа: кнопки, поля и реплики

Это сценарий демонстрации на синтетических данных. Примеры текста ниже учебные, не факты об оборудовании. Названия сверены с текущим исходным кодом интерфейса. Для повторения сквозной проверки: `./node_modules/.bin/playwright test -c tests/live/playwright.config.ts rehearsal-workflow.spec.ts`. Фактический итог хранится в verification/rehearsal-ui.json после успешного теста.

## Перед показом

Открыть http://127.0.0.1:8080. Подготовить локальные пароли из infra/.env: DEMO_ENGINEER_PASSWORD, DEMO_APPROVER_PASSWORD, DEMO_TECHNICIAN_PASSWORD, DEMO_VIEWER_PASSWORD. Не показывать файл с паролями аудитории. Роли переключаются через «Выйти» справа сверху и новый вход. Ссылки случая и плана сохранить вместе с параметром run.

Полный маршрут включает явное подтверждение синтетического случая, согласование плана, результаты каждого шага и отдельное закрытие. Непроверенные записи теперь доступны для приложения к результату; выбор не меняет их статус проверки.

## 1. Вход и свежий запуск

1. В поле «Пользователь» ввести `engineer`.
2. В «Пароль» вставить значение DEMO_ENGINEER_PASSWORD. Нажать «Войти».
3. Если открылась старая очередь, нажать «Сменить набор» в верхней полосе или «Новый запуск / другое время» в блоке воспроизведения.
4. В карточке с подписью «Синтетический расчет» выбрать «Время среза» → «Последний срез».
5. Нажать «Открыть сценарий» именно в этой карточке. Дождаться очереди.
6. Убедиться, что наверху SIMULATION. Для репетиции не перемещать виртуальное время после создания плана: новый анализ может сделать согласование устаревшим.

Говорить: «Это синтетический набор. Мы показываем процесс принятия решения, а не управление реальным оборудованием».

## 2. Открыть случай

1. Слева нажать «Очередь рисков».
2. Нажать название объекта ТП-177 в первом столбце таблицы. Если его нет, проверить фильтр «Приоритет»: «Все». Альтернативный пример: ТП-309.
3. В карточке посмотреть «Измерено», «Ожидалось», «Отклонение».
4. Над графиком нажать «Остаток», затем вернуть «Температура». В «Период» можно выбрать «72 часа».

Говорить: «Нас интересует отклонение от ожидаемой температуры с учетом режима, а не сама высокая температура. Индекс приоритета не является вероятностью отказа».

## 3. Где указать основание рассмотрения

На широком экране справа найти «Инженерный вывод». Внизу этого блока, после «Следующие проверки», расположена кнопка «Решение по случаю». На узком экране блок будет ниже графика.

1. Нажать «Решение по случаю».
2. В диалоге «Новое состояние» выбрать «На рассмотрении».
3. В поле «Основание» вставить:

> Учебный разбор ТП-177. Анализ показывает отклонение измеренной температуры от ожидаемой. Требуется проверить качество исходных данных и независимое подтверждение. Дефект пока не подтверждаю.

4. Нажать «Записать решение».
5. Проверить сверху: «Состояние: На рассмотрении».
6. Еще раз «Решение по случаю» → «Новое состояние: Ожидает доказательств».
7. «Основание»:

> Для продолжения учебного разбора требуется независимая проверка. Запрашиваю подтверждающие материалы; реальных измерений и термограммы в демонстрации нет.

8. Нажать «Записать решение».

Говорить: «Я явно принимаю случай в работу и фиксирую, чего не хватает для вывода. Система сохраняет автора и основание решения».

## 4. Где добавить доказательство

Это другое действие. Не искать кнопку с названием «Добавить доказательство».

1. В блоке «Доказательства и качество» нажать «Открыть записи».
2. Откроется боковая панель «Доказательства».
3. Прокрутить панель до заголовка «Добавить заметку».
4. В большое поле «Наблюдение» вставить:

> Учебная запись для репетиции. В синтетическом сценарии рассматриваем дополнительный нагрев ТП-177. Требуется сопоставить показания датчиков, нагрузку и независимую проверку. Реальная термограмма не приложена; физические измерения не выполнялись.

5. В поле «Основание добавления» вставить:

> Фиксация исходного наблюдения для учебного разбора и подготовки проверочного плана.

6. Нажать «Сохранить запись». Панель закроется.
7. Снова «Открыть записи»: убедиться, что текст появился. У новой записи ожидается «Не подтверждено». Закрыть панель крестиком «Закрыть».

Говорить: «Наблюдение описывает материал, а основание объясняет, зачем я его добавил. Само сохранение заметки не делает ее проверенным доказательством».

## 4а. Подтвердить только учебный случай

Для этой ветки репетиции используйте явно синтетическое допущение: независимая проверка в учебном сценарии подтвердила дополнительный нагрев. Не подтверждайте реальный дефект по заметке.

Перед решением добавить отдельную запись: «Открыть записи» → «Наблюдение»: `Учебный протокол: по условию синтетического сценария независимая проверка подтвердила дополнительный нагрев. Это вымышленные данные для отработки процесса, не измерения реального объекта.` → «Основание добавления»: `Учебный материал для демонстрации явного подтверждения человеком.` → «Сохранить запись».

1. «Решение по случаю» → «Новое состояние»: «Подтвержден человеком».
2. «Основание»: `Только учебный сценарий: принимаю синтетическое подтверждение дополнительного нагрева. Вывод не относится к реальному объекту.`
3. Отметить новый «Учебный протокол» в «Записи, на которых основано решение», а не исходное наблюдение.
4. «Записать решение». Ожидается «Подтвержден человеком».

Локальный Compose явно выдает engineer право case.confirm. В другой конфигурации его может не быть. Подтверждение случая не превращает заметку в проверенную запись.

## 5. Создать проект плана

Добавить начальные заметки нужно до создания плана. Добавление новых записей после отправки/согласования меняет основание плана и может потребовать пересмотра.

1. Внизу «Инженерного вывода» нажать «Создать проект проверки».
2. Откроется «Проект проверочных мероприятий». Просмотреть предлагаемые проверки.
3. В «Основание проекта» вставить:

> Учебный план для проверки причины отклонения температуры ТП-177. Проверяем телеметрию, сопоставляем режим и определяем необходимые подтверждения. Проект не является разрешением на работы с оборудованием.

4. Нажать «Создать проект». Откроется страница плана.
5. Сохранить адрес страницы плана. Вверху должно быть «Проект».

Говорить: «Система предлагает проверочные действия. Инженер оформляет из них проект, связанный с конкретным анализом и записями».

## 6. Уточнить проект

1. Прокрутить ниже таблицы «Шаги проверки» до «Редактировать проект».
2. Для каждого шага прочитать «Описание». Не заменять разные проверки одним одинаковым текстом.
3. В «Срок, ч после согласования» для репетиции можно поставить `48`.
4. В «Нужные подтверждения, через запятую» указать по смыслу шага, например `Учебный протокол проверки, Заключение исполнителя`.
5. Поле «Ответственный» уже содержит «Исполнитель» и недоступно для изменения.
6. В конце формы «Основание изменения»:

> Уточнены сроки и состав подтверждающих материалов для репетиции. Все результаты должны быть явно обозначены как учебные.

7. Нажать «Сохранить проект».

Говорить: «У каждого шага есть ответственный, срок и ожидаемые материалы. Пока это только проект».

## 7. Отправить на согласование

1. Под редактором найти «Передать на согласование».
2. Нажать. В открывшемся диалоге «Основание» заполнить:

> Передаю учебный проект на согласование. Состав проверок и сроки просмотрены. Управление оборудованием и реальные работы в демонстрацию не входят.

3. В «Подтверждающие записи» можно выбрать относящуюся к решению учебную заметку. Подпись «не проверено» сохраняется. Отклоненные записи недоступны. Для отправки список не обязан быть непустым.
4. Нажать «Записать решение».
5. Ожидаемое состояние: «На согласовании».

## 8. Показать разделение прав

1. Нажать «Выйти» справа сверху.
2. Войти как `viewer` с его локальным паролем. При необходимости открыть сохраненную ссылку плана.
3. Показать план: кнопки «Согласовать» у этой роли нет.
4. Снова «Выйти».

Говорить: «Наблюдатель видит материалы, но не принимает решение за согласующего».

## 9. Согласовать

1. Войти как `approver`. Открыть сохраненную ссылку плана.
2. Ниже «Шаги проверки» нажать «Согласовать».
3. В «Основание» вставить:

> Согласую состав и порядок учебных проверок. Это согласование плана, а не подтверждение дефекта или разрешение на переключения.

4. Нажать «Записать решение».
5. Ожидаемое состояние: «Согласован».

Говорить: «Решение принимает отдельный пользователь. Согласование плана не подтверждает дефект автоматически».

## 9а. Отметить планирование в случае

«Выйти» → `engineer` → сохраненная ссылка случая → «Решение по случаю» → «Мероприятия запланированы» → «Основание»: `Учебный проверочный план согласован, фиксирую переход к мероприятиям.` → «Записать решение».

## 10. Начать выполнение

1. «Выйти» → войти как `technician` → открыть ту же ссылку плана.
2. Нажать «Начать выполнение».
3. «Основание»:

> Начинаю учебную отработку проверочных шагов. Физические работы на объекте не выполняются.

4. Нажать «Записать решение». Ожидаемое состояние: «В работе».

Говорить: «Теперь действия переходят к исполнителю. Его результат позже должен проверить другой участник».

## 11. Добавить запись исполнителя

Делать после перехода плана в «В работе».

1. Вверху плана нажать «Открыть диагностический случай».
2. «Доказательства и качество» → «Открыть записи» → «Добавить заметку».
3. «Наблюдение»:

> Учебный результат проверки для репетиции. Подготовлено описание условий и вывода исполнителя. Реальных измерений, термографии и работ на объекте не выполнялось. Требуется отдельная проверка согласующим.

4. «Основание добавления»:

> Фиксация учебного результата исполнителя по проверочному плану.

5. «Сохранить запись». Вернуться по сохраненной ссылке плана.

## 12. Записать результат каждого шага

1. Прокрутить до «Результаты шагов».
2. Нажать «Результат шага 1».
3. Откроется «Записать результат проверки».
4. В «Заключение» подготовить текст по конкретному шагу, например:

> Учебный шаг проверки телеметрии разобран. Описаны данные и условия, необходимые для проверки. Реальные измерения не проводились. Передаю результат на независимую проверку согласующему.

5. В «Подтверждающие записи» нужно выбрать соответствующий материал, затем нажать «Сохранить результат».

Запись с подписью «не проверено» можно выбрать. Это приложение материала, а не автоматическое подтверждение. Повторить для **каждого** шага плана, указав вывод именно по этому шагу. Повторно записать уже сохраненный шаг сервер не позволяет.

## 13. Передать и проверить результаты

1. `technician`: «Передать на проверку» → «Основание»: `Учебные результаты всех шагов записаны. Передаю на независимую проверку.` → «Записать решение».
2. Ожидается «Ожидает проверки».
3. «Выйти» → `approver` → та же ссылка плана.
4. Прочитать заключения всех шагов. «Записать завершение» → «Основание»: `Учебные результаты и приложенные материалы просмотрены. Завершаю проверку плана.` → «Записать решение».
5. План становится «Выполнен», результаты шагов «Проверен». Случай еще не закрыт.

## 14. Отдельно закрыть случай

1. «Выйти» → `engineer` → ссылка случая.
2. «Решение по случаю» → «Проверка результата» → «Основание»: `Учебный план выполнен и проверен согласующим. Перехожу к итоговой проверке случая.` → «Записать решение».
3. «Выйти» → `approver` → та же ссылка случая.
4. «Решение по случаю» → «Новое состояние»: «Закрыт».
5. «Основание»: `Учебный план выполнен, результаты проверены. Закрываю демонстрационный случай; решение не относится к реальному оборудованию.`
6. В «Записи, на которых основано решение» отметить запись с результатом исполнителя.
7. «Записать решение». Состояние случая: «Закрыт».

Говорить: «Завершение плана и закрытие случая являются разными решениями. Ничего не закрывается автоматически».

## Финальная реплика и история

В карточке случая прокрутить вниз до «Ход рассмотрения»: показать авторов и причины решений. Наверху «Экспорт JSON» сохраняет данные; «Печать» открывает печатное представление.

Говорить: «Мы прошли от наблюдения к оформленному решению. Видно, кто добавил материал и кто согласовал действие. Это демонстрация процесса; точность на реальном оборудовании здесь не доказывается».

## Если кнопка не видна

- «Добавить заметку» отсутствует: проверить SIMULATION, роль engineer/technician, связь с сервером; прокрутить боковую панель вниз.
- «Решение по случаю» ниже видимой области: искать внизу «Инженерного вывода», а не в верхнем заголовке.
- Нет «Согласовать»: войти как approver; план должен быть «На согласовании».
- Кнопка согласования неактивна и есть «План требует повторной проверки»: изменились анализ/записи. Вернуться в случай и создать новый актуальный проект; простое обновление страницы не отменяет проверку ревизий.
- Нет «Результат шага N»: роль technician, план «Согласован»/«В работе»/«Ожидает проверки». Сохранять результат можно только после «Начать выполнение».
- Нет «Закрыт»: состояние случая еще не «Проверка результата» либо нет права закрытия. Завершенный план сам не переводит случай в это состояние.
