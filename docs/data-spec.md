# Экспериментальные данные и демонстрационные сценарии

## 1. Что уже подготовлено

В `data/` — **синтетический** набор с фиксированным seed=20260925, не выгрузка реального объекта. Генератор `scripts/generate_demo.py` работает на стандартной библиотеке Python 3.10+, без API, GPU или платных сервисов. Его назначение — проверить инженерную логику, обработку источников и демонстрационный workflow; не оценить реальную точность предсказания отказов.

По умолчанию: 30 суток, от 24.06.2026 07:40 UTC до 24.07.2026 07:40 UTC включительно; интервал 300 секунд; **7 трансформаторов × 8641 отметка = 60 487 широких строк**; 31 событие выключателя; 31 суточное измерение относительного индикатора ЧР. Всего 9 активов. Начало выбранного 14-дневного диапазона на UI может совпасть с диапазоном слайда; сам набор длиннее для baseline и истории.

Одна широкая строка содержит нагрузку, ambient, температуру фазы A, независимое измерение той же точки и температуру фазы B. Это не 60 487 отдельных scalar measurements: adapter разложит строку на отдельные измерения с собственными metric/sourceId. Период начального установления модели исключается из приёмки диагностики либо явно используется как warm-up.

Ожидаемые выводы — цели будущих тестов алгоритма. В поставленном пакете тестируется сам набор, а не готовый диагностический сервис.

## 4. Физическая и статистическая правдоподобность

Нагрузка и ambient имеют суточные циклы; тепловое состояние инерционно зависит от нагрузки; шум основного датчика автокоррелирован. Истинное тепло отражается в основном и независимом канале, а смещение основного датчика — только в нём. Фаза B даёт дополнительное сравнение. Эти признаки позволяют отличать сценарии без магического AI, но не моделируют все реальные причины, охлаждение, старение и положение ИК-камеры.

Текущая генерация — намеренно простая контролируемая система. Для честной следующей оценки отдельно создать закрытый набор: другой tau и коэффициенты, неопределённые ambient-лаги, независимые датчики с собственной ошибкой, нормальные нестационарные режимы, смешанные дефекты. Заморозить параметры до запуска. Не обучать и не оценивать на одинаковых сценариях с единственным seed.

## 5. REFERENCE не смешивать с SIMULATION

В `contracts/examples/reference-*.json` воспроизведены значения слайда. Индекс 7,2, 80/68/12 и сроки сохраняются как иллюстрация. `reference-chart-reconstruction.json` — стилизованная реконструкция 15 точек, **не точная оцифровка** и не исходная телеметрия. Полоса ±3 °C выбрана для графического примера, не является доверительным интервалом.

Числа SIMULATION не обязаны совпасть с иллюстрацией. Нельзя записать 7,2 в computed AnalysisRun, чтобы «доказать совпадение с презентацией». В режиме simulation значения появляются только после расчётного backend. До его создания прототипный экран должен честно использовать reference badge или contract mock badge.

## 6. Работа с доказательствами

Фотореалистичные «термограммы» не генерировались. В наборе присутствует явно маркированная запись без изображения. Она **не подтверждает** дефект и не должна рисоваться как настоящее обследование. Для демонстрации загрузки добавить простой JSON/CSV с контрольными измерениями и заключением «синтетические данные»; при необходимости изображения использовать предоставленные владельцем разрешённые образцы с provenance.

Давность термограммы три дня соответствует иллюстрации. Признак устаревания вычисляется по policy этого случая, а не общей догме «любая термограмма годна 48 часов».

## 7. Воспроизведение

```bash
# Из корня распакованного пакета; создавать в НОВОМ или пустом каталоге.
python scripts/generate_demo.py --out ./generated-run --seed 20260925 --days 30

# Проверка поставленного набора; JSON Schema-тесты требуют jsonschema.
python -m pip install -r requirements-validation.txt
python tests/test_blueprint.py --report verification/local-data-checks.json
```

Генератор отказывается перезаписывать непустой каталог, чтобы случайно не затронуть чужие данные. gzip имеет фиксированный mtime, manifest — контрольные суммы. Одинаковые версия Python/генератора/seed воспроизводят те же файлы; разные seed меняют шум. Для воспроизводимости между разными платформами окончательно фиксируется и Python image на этапе scaffold.

## 8. Демонстрационный сценарий на 7–10 минут

Открыть reference-кейс и объяснить, что это воспроизведение слайда. Затем переключиться на simulation, создать новый run и пройти от нормального периода к росту остатка. Открыть доказательства и показать неполную термографию. Сравнить с ростом нагрузки без дефекта и дрейфом датчика. Подготовить проверочный план, передать на согласование, войти как approver, утвердить. Приложить синтетический результат и показать, что падение температуры не закрывает случай автоматически. Завершить демонстрацией потери данных и неизвестного состояния.

Переключение ролей должно использовать серверную авторизацию seeded-пользователей, а не изменять permission в localStorage. Истинные данные из truth не показывать как источник уверенности системы.
