# ЭнергоДиагностика · локальный прототип

Советчик для демонстрации цепочки **наблюдение → расчет → гипотеза → проверочный план → решение инженера**. React/FastAPI/PostgreSQL и отдельный worker. Внешний AI не нужен. Управление оборудованием, изменение уставок и автоматическое подтверждение дефекта исключены.

## Запуск

Нужен запущенный Docker Desktop. Из основного checkout:

```bash
python3 scripts/init_local_env.py
docker compose --env-file infra/.env -p energy-diagnostics -f infra/compose.yaml up --build -d --wait
```

Открыть **http://127.0.0.1:8080**. Пользователь `engineer`, пароль в локальном `infra/.env`, строка `DEMO_ENGINEER_PASSWORD`. Скрипт создает случайные пароли, сохраняет существующие и не выводит секреты. Для согласования использовать `approver`, для результатов `technician`, для просмотра `viewer`, с соответствующими паролями из того же файла. Роль проверяется сервером. После выхода текущая ссылка на случай/план сохраняется.

[Локальный runbook](docs/runbook/LOCAL.md) описывает остановку, восстановление и backup. [Сценарий показа на 7–10 минут](docs/runbook/DEMO.md). Изолированная галерея компонентов: `/gallery`.

## Что можно показать

- Очередь рисков, качество и свежесть данных; переход в диагностический случай или карточку актива.
- Измеренную и ожидаемую температуру, остаток и тренды 24/72 часа, неподтвержденные гипотезы и происхождение расчета.
- Доказательства, проект плана, серверное согласование, запись результата, проверку и закрытие с журналом действий.
- Виртуальное время: пауза, шаг, скорости ×1/×10/×60. Для другого начала выбрать новый запуск; старые данные не стираются.
- Печать/JSON с режимом, временем и версиями. Источники и границы применимости метода доступны отдельным экраном.

**REFERENCE** воспроизводит анализ и схему слайда 29. Иллюстративный план из fixture не засеивается; рабочий план демонстрируется в SIMULATION. Числа 7,2/10, 80/68/+12 °C иллюстративны. 7,2/10 не означает 72% вероятности отказа. Схема имеет источник «модель»; состояние Т-2 неизвестно.

**SIMULATION** реально рассчитывается из `data/observations`: 7 трансформаторов, выключатель и кабельный участок, 30 суток. `data/truth` не монтируется в runtime. Диагноз не выбирается по имени сценария или assetId. Тепловая методика применяется только к трансформаторам; выключатель и кабель честно отмечены как неподдерживаемые данным методом. Недостаток/спорность данных дает неизвестную оценку. Вероятность отказа не рассчитывается, forecast выключен.

```bash

npm ci

npm run test:python
npm test
npm run build
npm run test:e2e
# На работающем локальном Compose, с паролями в infra/.env:
uv run --frozen python scripts/smoke_local.py
uv run --frozen python scripts/check_live_workflow.py
./node_modules/.bin/playwright test -c tests/live/playwright.config.ts
```

Python 3.13.5, Node 25.1.0/npm 11.13.0, uv 0.12.15; зависимости зафиксированы lockfiles. Браузер устанавливается при необходимости командой `PLAYWRIGHT_SKIP_BROWSER_GC=1 ./node_modules/.bin/playwright install chromium`. Это проектные зависимости, не плагины/skills/hooks.

Фактические результаты: `verification/CORE_REVIEW.md`, `verification/WORKFLOW_REVIEW.md`, `verification/live-*.json`, скриншоты `verification/live-*.png`. Независимая приемка G4: локальный advisory demo принят на production commit `2e3617d`; отчет `verification/PROTOTYPE_ACCEPTANCE.md`, 3 live Playwright-теста и 24 просмотренных скриншота. Удаленный CI/публикация не выполнялись.

## Источники и ограничения

Исходный blueprint, prompts и fixtures сохранены. Визуальная спецификация: [DESIGN.md](DESIGN.md); численная семантика: [docs/diagnostics.md](docs/diagnostics.md); контракты: [contracts/README.md](contracts/README.md); план приемки: [docs/acceptance.md](docs/acceptance.md). Этапы и изменения зафиксированы в `handoffs/`.

Это демонстрационный продукт на синтетике, не промышленная диагностика и не подтвержденная точность на реальном парке активов. Нет промышленного коннектора, реальных термограмм, интеграции с ТОиР и эксплуатационной сертификации. Подключение объекта требует паспортов, согласованной привязки датчиков, регламентов, прав и отдельной проверки модели.
