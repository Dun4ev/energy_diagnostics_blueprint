## Что здесь уже есть

Подробный `design.md`, функциональная/численная/архитектурная спецификации, план приёмки, исследование tools и форумов, 11 отдельных Codex prompts, три instruction-only skills, конфигурация сменного бренда, стартовые JSON Schema и референсные fixtures. Также есть реально исполняемый генератор и созданные им синтетические данные с проверками.

**Чего ещё нет:** готового frontend/backend, работающего workflow согласования, реализованного диагностического сервиса, промышленного коннектора, выполненных вызовов Jev. Эти части описаны заданиями для реализации. Полный OpenAPI нужно дополнить и зафиксировать на этапе01; текущие JSON Schema определяют Measurement/AnalysisResult, а не весь будущий сервер.

## Начать здесь

Сначала прочитать `design.md`, затем `docs/implementation-plan.md`. Папку открыть в Codex и передать `prompts/00-preflight.md`. Он проверит фактическое окружение и сформирует план без самовольной реализации/установки. После согласования запустить01. Параллельные агенты02–05 работают только после заморозки контрактов; UI features06 после готовности общей оболочки;07 интегрирует;08 независимо проверяет.09 Jev — необязательный эксперимент;10 — шаблон будущего расширения.

Начальное сообщение для Codex находится в `START_HERE.md`.

## Числовые ограничения, которые нельзя потерять

Индекс7,2/10 в слайде — пилотная шкала с неизвестной формулой, не72% вероятности отказа. Окно7–14дней прямо не является прогнозом даты отказа. Осмотр≤48ч — отдельный срок следующего действия. Пропуск/устаревание измерений не превращается в низкий риск.

Сохранены два режима: REFERENCE — значения презентации с явным origin; SIMULATION — реальный будущий расчёт по observations. Числа генератора не подгоняются под картинку. Референсная историческая линия стилизованно реконструирована, не извлечена как настоящая телеметрия. Полная работоспособность MVP не должна зависеть от внешней AI-модели.

## Синтетический набор и проверки

30 суток, шаг5мин, 7трансформаторов, **60 487 широких строк**; дополнительно31событие выключателя и31суточное измерение кабеля, всего9активов. Есть нормальный режим, нагрев, изменение нагрузки, дрейф датчика, пропуски/залипание/выброс, восстановление и ускоряющееся ухудшение.

В среде подготовки прошли **19 из19 проверок**, включая воспроизводимость seed, хеши, временные интервалы, разделение truth/observations, заложенные сценарии, JSON Schema и контраст выбранных токенов. Версии среды и точный перечень в `verification/data-checks.json`. Это не оценка эксплуатационной точности и не тесты ещё не созданного приложения.

```bash
# Выполнять из корня пакета. Для генератора достаточно Python3.10+.
python scripts/generate_demo.py --out ./generated-run --seed 20260925 --days 30

# Установка нужна только для JSON Schema-проверок, предпочтительно в venv.
python -m pip install -r requirements-validation.txt
python tests/test_blueprint.py --report verification/local-data-checks.json
```

Генератор не перезаписывает непустую папку. Сервисам будущего приложения монтировать только `data/observations`, не `data/truth`. Никакая реальная термограмма не выдумана: evidence fixture прямо указывает отсутствие изображения.

## Работа с инструментами и реальным объектом

Сторонние репозитории/плагины здесь не устанавливались. Использовать уже доступный Product Design/frontend-design и один browser QA путь; опционально Impeccable для review. Не добавлять пять конфликтующих дизайн-наборов. Ссылки/способы установки в исследовании проверены на дату подготовки, перед фактической установкой проверить версии, лицензии, hooks и разрешения.

Для реального пилота нужны паспорта/места датчиков/теги/регламенты/история подтверждённых исходов/права/интеграция. Прототип — советчик. В нём не должно быть команд выключателю, изменения РЗА или автоматического назначения отключения.
