# План реализации и организация Codex

## 1. Результат первой итерации

Рабочая локальная система, а не только кликабельная картинка: replay источника → валидация → численная диагностика → согласованная очередь/случай → проверочный план → серверное согласование → сохранённый результат/история. Все функции работают без внешней AI-модели. Внешний сервис Jev — отдельный необязательный эксперимент после этого результата.

Ориентир планирования, не обещание срока: визуальная оболочка 1–3 сфокусированных рабочих дня; вертикальный функциональный прототип обычно стоит планировать на 8–15 сфокусированных дней; ещё резерв на исправления после первой демонстрации. Это моя оценка объёма выбранного MVP, не данные из презентации/независимый benchmark. Работа одного человека по вечерам занимает больше календарного времени. Промышленная интеграция и валидация в эти оценки не входят.

## 2. Граф зависимостей

```text
00 preflight (без изменений кода)
       ↓ подтверждение scope
01 foundation + contracts + build/test skeleton
       ↓ G1: общий контракт и fixture проходят проверки
  ┌────┼─────────────┬──────────────┐
 02 ingestion     03 core      04 backend      05 UI shell
  └────┼─────────────┘               └──────────┬─────┘
       │                                 06 UI features
       └─────────────────┬───────────────────┘
                         07 integration/replay
                              ↓
                         08 independent QA
                              ↓ G4: принят вертикальный срез
                         09 optional Jev spike
```

Четыре параллельных потока — максимум по текущему разделению владельцев. Интегратор может быть пятой сессией, но не должен параллельно изменять те же файлы. Сначала один проход по контрактам; попытка стартовать 5 свободных агентов с общим «сделайте продукт» создаёт конфликтующие DTO/состояния.

## 3. Контрольные точки

| Gate | Условия прохождения |
|---|---|
| G0 Scope | Зафиксированы MVP/out-of-scope, папки, инструменты, режим demo, unresolved assumptions |
| G1 Contracts | Входы/выходы/состояния/API заморожены; типы сгенерированы; fixture проходит; базовые тестовые команды доступны |
| G2 Modules | Модули проходят собственные тесты на контракте; есть handoff и список ограничений |
| G3 Integrated slice | UI работает на реальном local backend без MSW, данные и решения сохраняются, replay корректен |
| G4 Acceptance | Численные, workflow, безопасность и визуальные проверки пройдены; отчёт не содержит ложных заявлений о готовности |
| G5 Optional AI | Есть сравнительный результат Jev; без выигрыша интеграцию не включать |

При непрохождении gate следующий этап не объявляется завершённым. Screenshots одного happy-path недостаточны для G4.

## 4. Владение файлами

| Агент | Пишет | Только читает |
|---|---|---|
| Integrator | root configs, lockfiles, `packages/domain_contracts`, `contracts`, `apps/worker`, infra, интеграционные тесты | Все module paths |
| Ingestion | `packages/ingestion`, `tests/ingestion` | core, API, web, canonical DTO, reference data |
| Numerical core | `packages/diagnostics`, `tests/diagnostics` | DTO, policy, observations; truth только отдельным evaluation test runner |
| Backend | `apps/api`, `tests/api` | contracts, core, web; запрос новой зависимости через integrator |
| UI shell | `apps/web/src/design-system`, `apps/web/src/shell`, `tests/ui-shell` | contracts, feature modules, canonical config |
| UI features | `apps/web/src/features`, `tests/ui-features` | shell/tokens/contracts; registration exports в свой файл |
| Independent QA | `tests/e2e`, `verification`, `handoffs/review-*` | Production code; не исправляет молча проверяемый код |
| Optional AI | `packages/decision_adapters`, `tests/decision_adapters`, отчёт spike | все production modules/guardrails |

Один root package manager/lockfile принадлежит интегратору. Остальные описывают потребность, но не запускают одновременные установки с перезаписью lockfile. Общий router собирается из экспортов features интегратором, не редактируется несколькими агентами.

## 5. Как запускать независимые сессии

После G1 создать отдельные Git branches/worktrees для ingestion, core, backend и UI shell. Codex документирует использование worktrees: https://developers.openai.com/codex/app/worktrees . Не требовать нестандартной системы оркестрации для 4 потоков.

Каждой сессии передать только свой prompt, `AGENTS.md`, обязательные разделы спецификации и frozen contract commit. Не загружать каждый раз всю презентацию, все исследования и все generated CSV в основной контекст. Визуальному агенту нужен screenshot; вычислительному — diagnostics/data contract; reviewer получает diff+tests+acceptance.

При появлении RFC остановить только зависимую часть, не выдумывать временный обход. Интегратор выпускает обновлённый контракт, затем ветки синхронизируются. При merge сначала проверка чужого diff, затем tests, затем browser smoke. Каждый этап — небольшой проверяемый commit.

## 6. Обязательный handoff от любого агента

```text
Модуль / ветка / базовый commit:
Изменённые файлы:
Какие входы принимает и какие выходы выдаёт:
Реализованные требования:
Команды проверок и фактические результаты:
Непроверенное / известные ограничения:
Новые зависимости и причины:
Есть ли изменение контракта (ссылка RFC):
Как воспроизвести демонстрацию:
Что должен сделать интегратор:
```

«Готово» без команд и результатов не является закрытием. Не писать, что тесты прошли, если они не запускались. Не улучшать чужие папки «заодно». Не скрывать правки под formatter всего репозитория.

## 7. Порядок демонстрации владельцу продукта

Сначала показать три согласованных экрана, объяснение индекса и отсутствие управляющих действий. Затем отдельно продемонстрировать рост остатка, нормальный рост от нагрузки, сомнение в датчике и обрыв данных. Пройти согласование и сохранение после перезапуска. Собрать замечания по роли/терминам/доказательствам, а не обещать дату отказа оборудования.

Для реального пилота следующий контракт включает доступ к историческим данным и инженерную приёмку модели. Полная система цифрового двойника, изображённая в презентации, не включается автоматически в этот MVP.
