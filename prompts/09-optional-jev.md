# 09 — Необязательный Jev spike после работающего MVP

Предусловие: G4. Не меняй MVP так, чтобы он зависел от Jev. Сначала нужен разрешённый доступ к сервису и политика данных; без них выполни только offline контракт/benchmark harness и укажи, что реальных вызовов не было.

## Прочитать

AGENTS.md; diagnostics раздел9; tools-and-research; официальный TypeSafe API/SDK на момент реализации; awesome-jev только как справочник. Проверь лицензию, версии и реальные условия сервиса. Не предполагай наличие открытых весов/on-prem режима.

## Владение

OWNED: `packages/decision_adapters`, `tests/decision_adapters`, `verification/JEV_SPIKE.md`, handoff/RFC. READ-ONLY: core, policy, case/workflow transitions, API/frontend contracts/permissions. Включение в продукт — отдельное решение интегратора.

## Выполнить

Определи порт `suggestEvidenceRequests(validatedSummary, allowedActions)`. Передавай только проверенное краткое резюме и allowed action codes, без сырых корпоративных файлов/секретов. Используй структурированный выбор/ranking с abstain, не проси модель вычислить физику или вероятность отказа. Типизированный результат проверяй отдельно; forbidden code/invalid schema/timeout→rule fallback.

Сравни deterministic rules и Jev на фиксированном expert-labelled наборе: пропуск необходимой проверки, лишние меры, ошибочная уверенность при недостатке данных, соблюдение allowed actions, устойчивость к prompt injection в заметках, задержка и стоимость. Часть кейсов удержи до финального сравнения. Не считать возвращённую confidence эмпирической вероятностью дефекта.

Текстовые объяснения чисел остаются из templates; решения/утверждения/статусы не меняются. Нет внешнего запроса на каждый telemetry sample. Ключ backend-only через env; network logging не содержит секрет/полные данные.

## Приёмка G5

Отчёт показывает реальную выборку, baseline, версии, вызовы/ошибки/метрики, ограничения и решение keep/remove. Без явного полезного выигрыша не включай runtime интеграцию. Нельзя написать «Jev повышает точность» без проведённого сравнения и определения метрики.

## Общие ограничения и завершение

Соблюдай AGENTS.md. Не изменяй READ-ONLY пути и чужие незакоммиченные изменения. Новое поле/зависимость/общая настройка — RFC интегратору, не самовольный обход. Не расширяй задачу до полного цифрового двойника. Не устанавливай сторонние skills/hooks и не подключай внешние сервисы без отдельного разрешения. Не используй truth как вход runtime.

В конце создай `handoffs/09-jev.md`: базовый commit, изменённые файлы, входы/выходы, выполненные требования, фактические команды/результаты, непройденные проверки, ограничения и инструкции интегратору. Не объявляй работу завершённой только по успешному build. Честно раздели созданное, протестированное и предложенное.
