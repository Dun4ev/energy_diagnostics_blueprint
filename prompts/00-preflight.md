# 00 — Инвентаризация и план, без реализации приложения

Ты — технический руководитель прототипа советчика по диагностике энергетических активов. В рабочей папке находится подготовленный blueprint. Сначала установи фактическое состояние репозитория, окружения и локальных tools. Не начинай реализацию всего приложения.

## Прочитать

`README.md`, `AGENTS.md`, `design.md`, `docs/source-review.md`, `docs/architecture.md`, `docs/implementation-plan.md`, `contracts/README.md`. Визуально изучи `references/slide-29.png`. Для tool выбора — `docs/tools-and-research.md`; не надо отправлять себе все CSV и PDF как текст.

## Владение

OWNED: только `handoffs/PREFLIGHT.md` и предложения RFC. READ-ONLY: весь остальной проект. Не устанавливай пакеты, не меняй конфигурацию пользователя, не запускай генератор в непустой папке, не создавай deploy.

## Выполнить

1. Проверь git status, текущую структуру, существующий код/lockfiles, доступные Python/Node/package manager/Docker и браузерные средства. Не выводи секреты из env.
2. Определи, какие Product Design/frontend-design/browser skills действительно доступны. Не путай ChatGPT plugins и local Codex tools. Не переустанавливай уже имеющееся. Предложи максимум один основной UI skill и один browser путь.
3. Сопоставь blueprint с наличным репозиторием. Обнаруженные противоречия, отсутствующие схемы и инженерные предположения выпиши отдельно.
4. Предложи самый короткий вертикальный срез: synthetic adapter → numerical core → API → queue/case/plan → approval. Укажи границы stages01–08, owned paths и gates.
5. Подтверди, что REFERENCE7.2 не вычисляется из формулы и не является72%; что real OT отсутствует; что `failureProbability=null`; что внешняя AI-модель необязательна.

## Приёмка

Один конкретный `PREFLIGHT.md` с решением по стеку/инструментам, вопросами-блокерами отдельно от некритичных предположений, командами следующего этапа. Не писать «готовый прототип создан». Заверши на G0 и жди выбора/подтверждения плана перед установкой и scaffold.

## Общие ограничения и завершение

Соблюдай AGENTS.md. Не изменяй READ-ONLY пути и чужие незакоммиченные изменения. Новое поле/зависимость/общая настройка — RFC интегратору, не самовольный обход. Не расширяй задачу до полного цифрового двойника. Не устанавливай сторонние skills/hooks и не подключай внешние сервисы без отдельного разрешения. Не используй truth как вход runtime.

В конце создай `handoffs/PREFLIGHT.md`: базовый commit, изменённые файлы, входы/выходы, выполненные требования, фактические команды/результаты, непройденные проверки, ограничения и инструкции интегратору. Не объявляй работу завершённой только по успешному build. Честно раздели созданное, протестированное и предложенное.
