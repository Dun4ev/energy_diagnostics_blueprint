# RFC: автономный режим стенда

База интеграции: `f126309`; в основной рабочей папке сохранены предыдущие незакоммиченные исправления счетчиков.

## Назначение и границы

`/stand` воспроизводит подготовленную учебную историю в отдельном read-only представлении. Численные срезы получаются текущим worker из синтетических observations; действия участников при подготовке пакета проходят существующие HTTP API с отдельными учебными ролями. Экран постоянно обозначает запись, режим SIMULATION и виртуальное время. Runtime не читает `data/truth/`.

## Интерфейсы

Пакет `apps/web/public/stand-data.json`, версия 1: provenance dataset/model/policy, два расчетных среза, восемь эпизодов, данные учебной истории и ссылки на объект/время для перехода. Вложенные RiskEntry, SeriesPoint, CaseSnapshot, Evidence, WorkPlan и AuditEvent сохраняют существующие DTO; новых бизнес-DTO, полей API, прав и миграций нет. Эпизод определяет вид, длительность и ссылку на срез, не диагноз. Пакет не содержит учетных данных, cookie или пользовательских записей.

`/stand/continue?scene=<id>` использует существующие auth, demo sessions и risks. Ключ идемпотентности и ID созданного запуска хранятся в sessionStorage текущей вкладки; живой запуск не наследует учебные решения. Переход возможен только при `demo.advance`. Обычные маршруты и контракты не меняются.

## Инфраструктура

Web получает собранный пакет как статический файл. Nginx разрешает адрес `api` при обращении к нему, чтобы статика могла запуститься без backend; опубликованным остается только loopback-порт. Изменение выполняется интегратором и должно проверяться как в полном Compose, так и в изолированном web.

## Проверка

Временный пакет проверяется на соответствие существующим моделям и provenance; отдельно проверяются автономный цикл, отсутствие сетевых запросов API, авторизация и идемпотентность перехода, роли, визуальное представление, сборка и проксирование API. Никакие операции стенда не подтверждают реальные дефекты или работы.
