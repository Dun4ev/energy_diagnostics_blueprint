# Handoff: режим стенда

База интеграции: `f1263096cf38a70e1421059142e92a25106203c2`, основная ветка `main`. Изменения оставлены без коммита и отправки. Ранее существовавшие незакоммиченные исправления счетчиков сохранены.

## Изменения

- `scripts/prepare_stand.py`, `apps/web/public/stand-data.json`: воспроизводимая подготовка записи через API и worker на отдельной временной SQLite-базе из observations. Используются временные учебные учетные записи; рабочая база, `infra/.env` и `data/truth/` скрипту не нужны.
- `apps/web/src/stand/*`: автономная витрина восьми эпизодов, проверка пакета, таймер и управление показом.
- `apps/web/src/features/StandContinue.tsx`, `standContext.ts`, `stand-flow.css`, изменения `DiagnosticsApp.tsx`, `chart.tsx`, `main.tsx`: переход к отдельному живому запуску с серверной идемпотентностью, ожиданием расчета, обработкой ошибок и панелью ведущего. Изменение графика для стенда сохраняет прежний режим на обычных экранах.
- `infra/nginx/default.conf`: отложенное разрешение адреса API для запуска статики отдельно от backend.
- `tests/frontend/stand-*.test.ts`, `tests/stand/*`: проверки часов, пакета, перехода, DTO, происхождения и повторяемости расчета.
- `docs/runbook/STAND.md`, `handoffs/RFC-stand.md`, `README.md`: инструкция ведущему и описание формата и точек интеграции. `verification/stand-preview.jpg` сохраняет проверочный вид витрины.

Ранее существовали изменения `case.tsx`, `plan.tsx`, `queue.tsx`, `support.tsx`, `count.ts` и `tests/frontend/count.test.ts`; они не относятся к реализации стенда.

## Совместимость и границы

Новых бизнес-API, полномочий, миграций или изменений действующих DTO нет. Пакет версии 1 содержит метаданные, существующие расчетные DTO и подготовленную учебную историю. `failureProbability` остается `null`; неизвестное качество не превращается в нулевой риск. Решения из записи в живой запуск не переносятся. Все показанные записи являются синтетическими и не являются действиями на оборудовании.

## Фактическая проверка

- `npm test` в локальном контейнере без сети: 51 тест пройден, включая 12 проверок пакета, 3 проверки перехода, 2 проверки часов и ранее существовавшие тесты. Два полных цикла и порядок эпизодов проверены тестом часов; два трехминутных цикла целиком в браузере не наблюдались.
- `npm run build` через сборку web-образа: typecheck и Vite прошли. Отдельный ESLint измененных файлов стенда и графика прошел. Vite сообщает о большом отдельном чанке библиотеки графиков.
- Четыре Python-проверки пакета прошли в backend-образе без сети: проверены существующие DTO, виртуальное время, версии, единицы, `failureProbability=null`, хеши observations и отсутствие полей учетных данных и truth. Независимая повторная подготовка подтвердила совпадение выбранных расчетов и обоих рядов.
- Статика и пакет открывались в изолированном web без API; во время проверенного автопоказа браузер запрашивал только локальные ресурсы. Ошибка недоступного пакета и повторная загрузка, ошибка недоступного API, пауза, ручной переход и полноэкранный режим проверены в браузере. Искусственный отказ самого расчета worker и повтор после него отдельно не воспроизводились. Автоматическая пауза при скрытии вкладки реализована, но в этой среде отдельно не подтверждена реальным изменением видимости вкладки.
- Ранний и поздний переходы проверены в браузере под engineer: открылся ТП-177 / Т-1 с нужным временем; повторное открытие позднего перехода не создало новый запуск. Возврат начал запись заново; созданный случай после возврата остался доступен.
- Живой сценарий с engineer, viewer, approver и technician проверен через отдельные авторизованные API-клиенты: отказ viewer на согласование 403, результат исполнителя сохранен, план завершен и случай закрыт. Все четыре роли не проходились повторно через браузерный интерфейс. В локальной базе сохранены созданные для проверки синтетические запуски и записи.
- Независимый визуальный обзор просмотрел основные эпизоды при 1920 × 1080, 1440 × 1000 и 390 × 844; найденные пересечение подписи оси с легендой и исчезновение маркировки при прокрутке исправлены и перепроверены. Встроенный браузер проверен отдельно интегратором, включая управление на фактическом размере окна.
- `git diff --check` прошел; Git сообщил только о преобразовании LF/CRLF в ранее измененных файлах счетчиков.

## Повторение и следующий шаг

Подготовка образов, запуск полного стека или только web без сети, открытие `/stand`, смена ролей и восстановление описаны в `docs/runbook/STAND.md`. В уже подготовленном проектном окружении доступны `npm test`, `npm run build`, `python -m unittest discover -s tests/stand -p test_package.py -v` и `python tests/stand/check_repeatability.py`. Для показа на другой машине следует заранее перенести подготовленные образы и проверить фактический экран и автономный запуск на месте. Установка зависимостей, публикация и автозапуск в эту работу не входили.
